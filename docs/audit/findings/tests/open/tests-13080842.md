# TestIsTestEnvironment has no false case — passes a constant-true impl

## Problem

tautological. Every table case expects `true`, including the "No test environment" case, so `IsTestEnvironment()` hardwired to `return true` passes.

## Evidence

fail2ban/logging_env_test.go:155:

```go
{
    name:     "No test environment",
    envVars:  map[string]string{},
    expected: true, // Will be true because we're running in test mode (os.Args contains -test)
},
```

No case asserts `false`.

## Impact

The function's whole purpose is to distinguish test from non-test; with no false case the test cannot detect a version that always returns true (which would, e.g., disable real sudo probing in production).

## Fix

Add a case that forces the false branch — e.g. run the detection against a synthesized `os.Args` without `-test.` and empty env — and assert `false`. If the detection reads `os.Args` directly, refactor it to take the args/env so a false case is constructible.
