# The git commit/push ask rules miss `git -C <dir> push` and `git -c … commit` forms

## Problem

`Bash(git commit *)` and `Bash(git push *)` match only that exact prefix.

## Evidence

Claude Code's permissions documentation ("What a Bash rule doesn't match") states Bash(git push *) does not stop `git -C . push origin main` or `git -c push.default=current push origin main`; the same applies to `git -C /abs/path commit`. Not run against the matcher; documented behavior.

## Impact

In auto mode those forms reach the classifier without the forced prompt.

## Fix

A PreToolUse Bash hook that asks for any command containing a git invocation with a commit or push subcommand, as the documentation recommends; owner-applied, since agent edits to this file are refused.
