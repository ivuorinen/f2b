# Test doubles, helpers and fixtures compile into the production fail2ban package; the release binary links `testing`

## Problem

The test/production boundary that the files' own headers state is not kept. mock.go, mock_runner.go, mock_sudo.go and test_helpers.go are non-_test files in package fail2ban. test_helpers.go imports `testing`. Test sentinels sit in GetDangerousCommandPatterns, which ValidateCommand checks.

## Evidence

`fail2ban/test_helpers.go:8` `"testing"`; `go tool nm f2b | rg ' testing\.'` shows testing.init in the binary; `deadcode ./...` lists every function in mock.go (31), mock_runner.go (11), mock_sudo.go (4) and test_helpers.go (18) as unreachable from main; `fail2ban/security_utils.go:58-62` "test sentinels (used exclusively in test fixtures)".

## Impact

The release binary carries package testing and about 60 test-only exported symbols, and the published API documents them.

## Fix

Move the cross-package doubles (MockClient, MockRunner, MockSudoChecker, builders, Setup* helpers) into a new `fail2ban/fail2bantest` package, move fail2ban-only helpers into `_test.go` files, move the test sentinels into a test fixture, and update imports in cmd tests.

## Status

Partly fixed 2026-10-27, left open.

Done:

- `fail2ban/test_helpers.go` no longer imports `testing`.
- `go list -deps . | grep -x testing` is empty.
- `go tool nm` on the built binary shows 0 `testing.` and 0 `fail2ban.Mock` symbols.
- The fail2ban-only helpers and the `DANGEROUS_*` sentinels moved to `fail2ban/fixtures_test.go`.
- `GetDangerousCommandPatterns` holds only real signatures; TestDangerousCommandSentinelsAreTestFixtures kills the sentinel mutant.

Remaining: mock.go, mock_runner.go, mock_sudo.go and the SetupMockEnvironment*/MustMock* helpers still compile into package fail2ban, so they stay in its exported API and in docs/api/fail2ban.md.

The `fail2bantest` move cannot be done as written. fail2ban's own internal tests use these doubles, and a package that imports fail2ban cannot be imported back by them (import cycle). The two ways out are:

- (a) Duplicate the doubles in `_test.go` files.
- (b) Convert the fail2ban tests that need them to an external `fail2ban_test` package. Many of these tests also use unexported functions.

Owner decision required: pick (a), pick (b), or accept the residual API surface.
